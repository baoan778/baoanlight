# 会话证据链与卡住诊断（设计）

- 日期：2026-11-18
- 状态：待评审
- 范围：子项目 1 / 5（后续依次为状态历史色带、按项目聚合、可操作与通知升级、机器人表达）

## 目标

让用户能回答两个问题，而不只是看到一个颜色：

1. 「这个颜色是怎么来的？」——展开会话，看到最近 5 条驱动它的事件。
2. 「它是不是卡住了？」——用静默时长 + 保守诊断语给出原因，而不是让用户自己猜。

## 非目标

- 不记录提示词、代码、文件内容或命令参数，只记元数据。
- 不落盘；重启即清。
- 不做全局诊断页（留给后续子项目）。
- 不改变任何状态推导规则、颜色语义或代理行为。

## 方案选择

采用「事件随 `/state` 快照内嵌下发」。相比独立 `/events` 接口，展开时零请求、与状态严格同步，不存在「展开瞬间会话已消失」的竞态；8 条 × 若干会话约 3–4 KB/帧，对 10 秒一次的心跳可忽略。

## 数据模型

每个会话在内存中维护一个环形缓冲：

```
events: [
  { at, source, event, state, detail, tookMs }
]
```

- `at`：事件时间（毫秒时间戳）
- `source`：`hook | log | file | api | mcp | wrap`
- `event`：原始事件名（如 `PreToolUse`、`exec_command_begin`）；没有事件名时可为空
- `state`：该事件推导出的状态
- `detail`：现有的一句话说明
- `tookMs`：上一个状态持续了多久

约束：

- 每会话最多 **8 条**，只保留最近 **2 小时**内的记录。
- 入环条件：非 pulse，且满足以下任一——状态变化、detail 变化、带 `event` 名。
- `detail` 沿用当前面板已经在显示的短标签，不额外采集新内容。
- 会话被删除（offline / TTL 清理）时清空该会话的缓冲。
- 缓冲只存在内存，进程重启即清空。

## 心跳与活动时钟

日志观察器（log / dsh / task / wbt）每 20 秒补报同状态心跳，用于防止忙碌会话因静默被丢弃。心跳不能算作「活动」，否则「卡住」永远不会触发。

实现：

- `setState` 增加可选参数 `pulse: true`，仅由观察器的心跳路径传入。
- `store.set` 对 pulse 上报照常刷新 `updatedAt`，但：
  - 不写入事件环；
  - 不更新 `lastEventAt`。
- 静默时长 = `now - lastEventAt`，而不是 `now - updatedAt`。

这样既保留「静默时仍显示忙碌（变暗）」，又能诚实区分「在跑」和「没有声音」。

## 诊断规则

默认阈值可在设置中修改（1–240 分钟，非法值回落默认）：

| 状态 | 默认阈值 | 文案 |
|---|---|---|
| busy | 15 分钟 | 疑似卡住：已 16 分钟没有新事件，可能卡在长工具调用，或进程/日志已停止。 |
| waiting | 10 分钟 | 已经等你 12 分钟，它仍停在确认这一步。 |
| error | 30 分钟（固定） | 错误已 30 分钟未处理。 |

- 静默时长始终显示，与是否触发诊断无关。
- 进程探测只作为附注，且只陈述「未探测到」，绝不写「已退出」：
  `（未探测到 Claude 进程；也可能是 npm 启动，无法确证）`
- 诊断文案不参与颜色计算，只出现在展开区。

## 接口

`/state` 快照的每个 session 增加 `events` 数组（只含有事件的会话）与 `lastEventAt`。

事件环不参与 SSE 的变更判定；快照内容变化才推送的现有逻辑保持不变。

## 界面

复用现有「多会话展开」：

- 展开某个会话后，在该会话行下方显示「为什么是这个颜色」。
- 最近 5 条事件按时间正序排列：`14:32:05 · hook · PreToolUse → 忙碌`。
- 末尾一行：`已静默 4 分钟`，超过阈值时追加诊断语。
- 只在展开时渲染，收起不占空间。
- 事件为空时显示「还没有可展示的事件，等待下一次上报」。

## 设置

「系统」组新增两个数字输入：

- 忙碌多久算卡住（默认 15 分钟）
- 等待多久提醒（默认 10 分钟）

写入 `config.json`，随配置导入/导出；非法值回落到默认值。

## 测试

- store：环形缓冲上限、2 小时裁剪、pulse 不写环也不刷新 `lastEventAt`、状态/detail 去重、会话删除清空。
- server：快照包含 `events` 与 `lastEventAt`；离线或 TTL 清理后事件消失。
- e2e：一串真实 Claude 钩子（提交 → 工具 → Stop）在快照里产生 3 条可读事件。
- UI：展开后时间线可见、阈值修改后诊断语出现/消失、设置重启后恢复。
- 回归：现有 229 逻辑 / 121 UI / 10 Electron 全部保持通过。

## 风险

- 事件环增加快照体积：上限 8 条/会话，实测可忽略；若后续代理数量显著增加，再改为按需接口。
- `pulse` 需要三个观察器同步修改；漏传会把心跳当活动，导致卡住诊断失效。用 store 单测锁定行为。
- waiting 状态本身不衰减是刻意设计；诊断语只描述「还在等」，不暗示故障。
