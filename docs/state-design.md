# 桌面瓦力状态灯 — 设计与交互说明

这份文档对应 overlay 的实现（`src/overlay/robot3d.js` + `src/overlay/ui.js` + `src/overlay/index.html`），
说明"一个机器人怎么同时表达多个软件的状态"，以及每条灯效、动作和交互的触发条件。
它同时也是验收清单：每一条都可以照着看一遍。

---

## 1. 三层光，各说一件事

一台机器人只有一个身体，但同一时刻可能有四个软件在跑。所以光被分成三层，
每一层只回答一个问题：

| 层 | 位置 | 回答的问题 | 谁来决定 |
|---|---|---|---|
| **主灯** | 胸口圆形指示灯（+ 自身点光源、桌面光池） | 现在最坏的情况是什么？ | 服务端 `PRIORITY` 聚合后的 `overall` |
| **灯环** | 桌面一圈 16 段 LED | 是哪几个软件，各自什么状态？ | 每个软件一段，固定顺序（deepseek→claude→codex→workbuddy），各按自己状态闪动 |
| **状态条** | 机身前脸 9 颗 LED + 帆杆信标球 | 它现在在干什么节奏？ | 最后上报的那个软件的节奏 |
| 仪表舱 | 舱内 8 条发光 bar | 每个软件一行，固定槽位 | `AGENT_ORDER`，与 DOM `#slot0..7` 一一对应 |
| 铭牌 | 舱下刻字 | 这是谁的舱？ | 永远显示主灯代表的那个软件，不轮播（见 3.1 第 4 条） |

主灯、灯环、状态条、仪表舱用的是**同一张颜色表**（`ui.js` 的 `COLOR` / `HEX`），
所以机器人不可能和自己身上的 DOM 镜像说法不一致。

## 2. 状态 → 表情 / 动作 / 灯效

| 状态 | 颜色 | 眼睛 | 眉（visor） | 头部 | 手臂 | 履带 | 主灯节奏 | 状态条 | 灯环 |
|---|---|---|---|---|---|---|---|---|---|
| `error` 报错 | 红 `#ff3b30` | 眯到 0.55，虹膜发红 + 头顶火焰 | 内端下压（怒） | 下垂 −0.10 + 24Hz 微抖 | 内收 + 颤抖，手指握紧 | 停 | 19Hz 硬闪（0.6↔3.0） | 交错闪光 | 该软件段 10Hz 频闪 |
| `waiting` 等待 | 黄 `#ffcc00` | 放大 1.06，滑落淡泪 | 外端上挑（疑问） | 3.1Hz 小幅摆动 + 跺脚顿挫 | 右臂举起挥动，左臂前伸 | 停 | 6.4Hz 大摆幅呼吸 | 波浪 | 该软件段呼吸 |
| `busy` 运行 | 绿 `#34c759` | 常态，瞳孔缓慢游移 | 平 | 0.72Hz 慢扫 | 双臂前伸泵动，手指捏合 | 前进 + 轮子转 + 扬尘 | 3.4Hz 脉动 | 两点跑马灯 | **该软件段内跑马灯** |
| `done` 完成 | 紫 `#b06bff` | 满足眯眼 0.78 | 平/微挑 | 原地转一圈 + 连跳两下 + 金色星星 | 摊开 | 停 | 1.3 稳定脉冲 | 稳定脉冲 | 该软件段稳定脉冲 |
| `idle` 空闲 | 白 `#dfe5ec` | 每 6.4s 眨一次 | 平 | 呼吸式微动 + 自主动作 | 垂放 | 极慢 | 常亮 0.5 | 微弱呼吸 | 慢、暗 |
| `unknown` 未知 | 灰 `#ccd3dc` | 瞳孔放大 1.2（惊讶） | 略歪 | 歪头 0.12 | 垂放 | 极慢 | 0.35 | 8Hz 低帧 | 暗呼吸 |
| `offline` 未连接 | 暗 `#4a5058` | 闭合到 0.05 | 落 | 低头 0.22（仍会自主微动） | 垂放 | 停 | 熄灭 | 熄灭 | 熄灭 |

> 灯环的「段」在多软件时按各自软件的状态**独立闪动**：出错的红段频闪、等待的黄段呼吸、
> 运行的绿段段内跑马、完成的淡绿段稳定脉冲——四段同时各自动，谁都不会被最坏的那一个盖住。

> 从忙碌进入「完成」或「空闲」的**那一瞬间**，机器人会原地转一圈 + 连跳两下（`bao:done`），
> 这是在「状态已经变了」这件事上给一个动作确认，而不是换颜色。

设计约束（都是刻意的）：

- **饱和绿只代表"正在干活"**。完成（`done`）用紫色 `#b06bff`、且是稳定脉冲而非
  跑马，与运行中的 `#34c759` 一眼可辨——「跑」和「跑完了」不能共用一个颜色；idle 用中性白。
- **红黄绿不参与氛围灯**。没有软件时灯环才用彩虹色缓慢扫过，有软件时每个色块都能被归因。
- **一帧只讲一个故事**。主灯管聚合、状态条管节奏，二者节奏一致（跑马灯 / 呼吸 / 频闪）；
  灯环则是「四个小故事」——每个软件一段、各按自己的状态闪动（红频闪 / 黄呼吸 / 绿跑马），
  互不抢戏，所以不会出现"主灯在呼吸而状态条在扫描"。

## 3. 多软件聚合（推荐方案，已实现）

### 3.1 分工

1. **聚合主灯**：取最坏状态（`src/store.js` 的 `PRIORITY`），同时把左侧点光源和桌面光池
   染成同色 —— 这是"这台机器现在状态如何"的唯一答案。
2. **灯环分区**：把 16 段切成连续弧段，一段一个软件，**顺序永远固定为
   DeepSeek Harness → Claude Code → Codex → WorkBuddy**（位置→软件映射稳定，状态变了
   灯也不挪位）。**每段按自己软件的状态独立闪动**——出错的红段频闪、等待的黄段呼吸、
   运行的绿段段内跑马——"谁在拖后腿"和"还有谁在跑"能同时看到；主灯代表的那一段
   额外提亮，所以"主灯在说谁"在灯环上也能定位。
3. **仪表舱 8 条 bar**：固定槽位（deepseek / claude / codex / workbuddy / 其他），
   与 DOM 的 `#slot0..7` 完全对应，位置永远不变——位置一变，"第 3 个灯是什么"就要重新学。
4. **铭牌**：永远显示**主灯代表的那一个软件名**（最坏者），不轮播——归属必须能一眼读到，
   不能等它转回来。
5. **pill 列表**：每个软件一行，固定顺序（与灯环/仪表舱一致），带 detail、fuel、静默时长；
   主灯代表的那一行有发光描边。超过 4 行折叠成 `还有 N 个`。

### 3.2 冲突规则

- 严重程度：`error > waiting > busy > done > unknown > idle > offline`。
- 同严重程度：按固定顺序 **DeepSeek Harness → Claude Code → Codex → WorkBuddy** 取第一个，
  不用「最近上报」——否则两个同级软件会让主灯来回跳。最近 3 秒内变化的软件只临时
  增强其通道高亮（`fresh`），不改变主状态优先级。
- 槽位上限 8（`store.js` 的 `MAX_SLOTS`）；超出时主界面提示
  `N more software running than the panel has slots for`，不静默丢弃。
- `warning`/`blocked`/`failed` 等别名在服务端统一归一（`ALIASES`），overlay 不重复判断。

### 3.3 状态来源与刷新

| 环节 | 实现 |
|---|---|
| 上报 | `POST /state`（hooks / adapters：`claude`、`codex`、`dsh-watch`、`log-watch`、`task-watch`） |
| 传输 | `GET /events`，SSE，首帧立即推送，25s 心跳；断线后指数退避重连（0.5s 起，上限 15s） |
| 频率 | 变化即推，无变化不重发；DOM 与 3D 都只在收到帧时更新 |
| 兜底 1 | 什么都没连：`offline`，灯全灭，只留环境光 |
| 兜底 2 | 发现进程但没有上报：`unknown`（`presence`），并提示 `bao connect claude` |
| 兜底 3 | SSE 断开：`body.disconnected`，灯光衰减到 16%，灯环熄灭——"不知道"比"猜一个状态"诚实 |
| 兜底 4 | 静默 90s：pill 变暗（`quiet`），灯仍按最后状态显示 |
| 老化 | busy 6h / idle 30m / 无活动 2m 清理；`error` 与 `waiting` **永不**自动消失 |

## 4. 鼠标与互动

| 触发 | 区域 | 反馈 | 持续 | 退出 |
|---|---|---|---|---|
| 指针移到眼睛上 | 两个镜片（raycast 命中） | 头 + 镜筒跟随指针，身体保持不动 | 持续 | 指针离开镜片 |
| 指针移到身体上 | 车壳（raycast 命中） | 整机转身：横向约 ±49°，车体绕地面前倾 | 持续 | 指针离开 |
| 指针在窗口外晃 | 整个桌面 | 只小幅侧倾（±0.2 rad），余光里"注意到你" | 持续 | 指针离开屏幕 |
| 单击 | 机器人任意部位 | 抬头、眨眼、跳一次 | 0.85s | 自动 |
| 双击 | 机器人任意部位 | 双臂举起挥手（肘部弯曲，手指张开） | 2s | 自动 |
| 右键 | 机器人任意部位 | 弹出尺寸条（整体缩放 70%–170%） | 直到点空白 / 再右键 / 点齿轮 | 手动 |
| 左键拖动 | 机器人任意部位 | 拖动整个窗口 | 拖动期间 | 松手 |
| waiting / error 出现 | — | 可选提示音各一次；单击即静音本次事件 | 一次 | 状态变化后自动解锁 |

实现要点：

- 指针位置由主进程 80ms 轮询后经 IPC 推送，所以窗口穿透（click-through）时依然可用；
  眼睛跟随在鼠标位于桌面任意位置时都生效。
- "眼睛区"与"身体区"用每 120ms 一次的 raycast 区分，不做逐帧检测。
- 交互不改变状态真相：点击只静音提示音，不隐藏灯，也不会把 error 改成 idle。

## 5. 尺寸调节

- **右键 → 尺寸条**：`−  [滑杆]  +  120%  ↺  ⚙`，点数值或 `↺` 一键重置回 100%。
- 缩放对象是 `#stage`（`--scale`），因此机器人、fuel 仪表、pill 列表**一起**缩放，
  而不是只放大灯。
- 范围 70%–170%；窗口以**底边中心**为锚重新定位，并 clamp 在屏幕工作区内，
  所以拖大不会跑出桌面。
- 3D backing store 的像素比随 scale 提高（`min(2, devicePixelRatio × scale)`），放大后不糊。
- 档位写进 `config.scale`，重启保持；齿轮进入完整设置（声音 / 穿透 / 列表 / 灯光亮度）。
- **滑杆不溢出**：`<input type=range>` 在 Chromium 里有约 129px 的内容最小宽度，
  若不加 `min-width: 0`，滑轨与滑块会从尺寸条/设置菜单里溢出来。尺寸条加宽到
  252px、设置菜单加宽到 220px，且两条滑杆都设 `min-width: 0`，确保控件完整落在容器内
  （回归测试 `the quick size slider stays inside its bar and the window` 与
  `the settings size slider stays inside its menu`）。
- **灯光亮度**：设置菜单里的「灯光亮度」50%–100% 只缩放发光件（主灯、灯环、状态条、
  眼睛光晕、手臂光带、信标）的强度，机器人本体材质与状态颜色、节奏都不变，所以状态
  仍可读。写进 `config.brightness`，重启保持。

## 6. 性能

| 手段 | 说明 |
|---|---|
| 帧率分档 | busy / waiting / error 目标 60fps；done / unknown / idle 30fps；offline 且无自主动作 15fps；`prefers-reduced-motion` 时整场 8fps（优先于状态档） |
| 自适应降级 | 连续 1s 实测 < 24fps → 像素比封顶 1x 并关闭扬尘，只降一次（避免来回抖动） |
| 埋点 | `#bot` 上的 `data-fps` 暴露实测帧率，验收时直接读 |
| 履带 | 44 个履带齿用 `InstancedMesh`，滚动只更新矩阵，不建对象 |
| 灯效 | 灯环 16 个材质的 emissive 直接改值；胸口灯叠加 additive 辉光 sprite。无后处理、无 bloom，所以透明窗口不会出现方形底 |
| 渲染 | `powerPreference: 'low-power'`，透明窗口，阴影贴图 1024，单方向光投影 |

目标：idle 常驻 CPU 占用可忽略；busy 时集成显卡 60fps、独显不唤醒。

## 7. 验收清单

### 7.1 自动化（`npx playwright test`，67 条全绿）

桌面拆解（2026-11-13，`test-ui/overlay.spec.js` 的 `the teardown happens on the desktop robot itself`）：
同一个浮层里换成可拆解的 49 件模型，窗口临时变大、相机自动后退，`Esc` 收起；
独立的 `/teardown/` 页面仍然保留，只用于录制/演示，不再是菜单入口。

独立拆解页（2026-11-12，`test-ui/teardown.spec.js`，页面在 `/teardown/`）：

- 零件清单与阶段数逐一对账（49 件 / 6 阶段，几何与面板同源）。
- 三段式（整机 → 依次拆解 → 全部零件）与滑块驱动同一个 `amount` 输入。
- 点选零件的标注带引线、朝外推、距边缘 ≥ 60px，不遮零件。
- 页面零控制台错误。

槽位由服务端下发（2026-11-12）：

- `a software the server adds shows up without touching the front end` —— 服务端多
  接一个软件，设置里的顺序表自动出现它，位置在已知软件之后。

颜色之外的第二条通道（2026-11-12）：

- `state changes are spoken, not only coloured` —— `#live` 以 `aria-live="polite"`
  念出「Claude Code 需要你」，且视觉上只有 1px，不参与布局。

性能预算（2026-11-12，`test-ui/perf.spec.js`）：

- `an idle robot draws at a fraction of the working rate` —— 空闲档位必须真的降到 15fps。
- `"reduce motion" slows the whole scene down` —— 系统「减少动态效果」下整场 ≤12fps。
- `the idle tier is not mistaken for a machine that cannot cope` —— 低帧率档位不得触发永久降级。
- `nothing rewrites the DOM while nothing changes` —— 状态不变时 `#labels` 零变更。

本地信任（2026-11-12）：

- `a write without the local token is refused` —— 没有 token 的写入 401，且灯不动。
- `a cross-origin page can neither drive nor read the robot` —— 跨源读写 403，且不回 CORS。
- `an agent name is shown as text, never as markup` —— 服务端字符串按文本渲染，不执行。
- `the page runs under the strict policy with no violations` —— CSP 下零违规，注入不执行。

更早的三条：

- `the scene is told which software owns which light, worst first` —— 聚合顺序与颜色契约。
- `right-click opens the size bar, and it scales the whole machine` —— 右键尺寸条 + 整体缩放。
- `the size bar closes when the click lands somewhere else` —— 点空白关闭。

原有 29 条继续通过（其中 `four software at once each keep their own segment`、
`the robot does not move when …`、`the robot is never clipped in …` 是硬约束）。

### 7.2 手动路径（约 3 分钟）

1. **单软件运行**：`bao set busy --agent claude` → 胸口绿灯脉动、前脸跑马灯、桌面一圈绿光跑马、履带滚动、手臂泵动。
2. **多软件**：再 `bao set waiting --agent codex`、`bao set error --agent workbuddy` →
   主灯变红（最坏者）、灯环出现红/黄/绿三段、铭牌写着红灯对应的那个软件名、右侧 pill 三行。
3. **完成**：`bao set idle --agent claude`（或显式 `bao set done`）→ 机器人原地转一圈 + 连跳两下，
   `done` 显示紫色并在 30 秒后回落白色，**不**变绿。
4. **眼睛跟随**：把鼠标缓慢停在两个镜片之间 → 头跟着转，身体不动、不甩尾。
5. **身体转身**：把鼠标沿机身从左划到右 → 整机（连履带）左右各转约 49°，能看到侧面与背面挂钩、散热格栅；左右履带反向滚（差速转向），胸口主灯与仪表舱始终可读。
6. **问候**：双击机器人 → 双臂抬起、肘部弯曲、手指张开挥手 2 秒。
7. **尺寸**：右键 → 拖动滑杆到 150% → 机器人、fuel 条、pill 一起变大，窗口向上长，不跑出屏幕；
   重启后仍是 150%。
8. **断连**：关掉 server → 机器人变暗、灯环熄灭、底部出现 `no connection — state unknown`；
   重开 server 后 0.5s 内开始重试，通常立刻恢复（连续失败则按 0.5s→15s 退避）。

### 7.3 视觉验收

- 履带与车壳之间能看到一条光缝，任何角度都不再"焊"在一起。
- 手臂完全在履带外侧，转到侧面时不会被履带切掉。
- 300px 宽度下：两只眼睛、眉板、铭牌、跑马灯、灯环色段都能分辨。
- 红/黄/绿三张脸并排截图时，仅看表情也能区分（眉 + 眼 + 姿态）。
- **界面全中文**：按钮提示、菜单、尺寸条、断连提示、状态动词、提示信息全为中文，
  不得残留英文（软件名 Claude Code / Codex / WorkBuddy / DeepSeek Harness 为产品名，保留原文）。
  回归测试 `the interface text is Chinese` 逐项核对。

## 8. 已确认的决策（2026-11-09 定稿）

以下六条是用户拍板的结论，实现已按此收敛；改动其中任何一条都要同步改测试与本文档。

1. **灯环用分区，不做轮播**：每段固定属于一个软件，位置稳定；轮播会丢掉"位置→软件"的映射。
   实现见 `robot3d.js` 的 `planRing()`。
2. **尺寸范围 70%–170%**：上限受 1080p 工作区高度限制，不放大到 200%。
3. **"完成"转圈 + 连跳，不闪绿**：颜色语义第一优先，绿永远等于"正在跑"；完成用动作确认，不用颜色。
4. **不做"窗口跟随鼠标"**：只有身体转向与头部/眼睛跟随，窗口位置由用户拖动决定。
5. **idle 不加"睡觉"动作**：空闲时保留呼吸、眨眼与瞳孔漂移，保证"还活着"可读。
6. **提示音默认关闭**（`config.sound=false`），仅在设置里开启；busy / waiting / error / done 各一套音高（idle / offline 静默）。

## 9. 情绪 / 自主 / 互动（后加的活物感层）

这些是「状态灯」之上的第二层，全部**只做动作、不占状态颜色**——语义表（第 1 节）仍是唯一真相。

| 类别 | 触发 | 表现 |
|---|---|---|
| 出错表情 | `error` | 头顶火焰 + 虹膜发红 + 眉内压下压 |
| 等待表情 | `waiting` | 滑落泪滴 + 跺脚顿挫 |
